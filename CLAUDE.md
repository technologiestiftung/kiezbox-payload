# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

Kiezbox landing page for Technologiestiftung Berlin (TSB): a Payload CMS 3 + Next.js 16 (App Router) site backed by Postgres, with a fully block-based, editable website via the Payload admin panel. Built from the Payload website template.

## Commands

- `npm run dev` — start Next.js dev server (frontend + admin) at `localhost:3000`, admin at `/admin`
- `npm run build` — production build (`postbuild` runs `next-sitemap` automatically)
- `npm start` — start the production server (after `build`)
- `npm run lint` / `npm run lint:fix` — ESLint (flat config: `next/core-web-vitals` + `next/typescript`)
- `npm run generate:types` — regenerate `src/payload-types.ts`; run after any change to `src/collections/`, `src/Header/`, `src/Footer/`, or `src/payload.config.ts`
- `npm run generate:importmap` — regenerate the admin import map after adding/changing custom admin components
- `npm run payload <subcommand>` — Payload CLI passthrough, e.g. `migrate`, `migrate:create`, `migrate:status`
- `npm run test:int` — Vitest integration tests (`tests/int/**/*.int.spec.ts`, jsdom)
- `npm run test:e2e` — Playwright e2e tests (`tests/e2e/**`); auto-starts the dev server against `localhost:3000`
- `npm test` — runs `test:int` then `test:e2e`
- Single Vitest file: `npx vitest run --config ./vitest.config.mts tests/int/api.int.spec.ts`
- Single Playwright file: `npx playwright test --config=playwright.config.ts tests/e2e/frontend.e2e.spec.ts`
- Local Postgres for dev/tests: `docker compose up -d` (Postgres on `localhost:5433`, Adminer on `localhost:8080`)

## Architecture

**Payload config** (`src/payload.config.ts`) registers collections (`Pages, Posts, Media, Categories, Users`), globals (`Header, Footer`), the Postgres adapter (`push: false` — schema changes go through migrations, not push mode), Lexical rich text, S3-compatible storage, and a `jobs` queue gated by `CRON_SECRET` (Vercel Cron).

**Routes** (`src/app/`) split into two route groups:

- `(frontend)/` — public site: home, `[slug]` dynamic pages, posts, search, sitemaps, live-preview/draft-exit routes.
- `(payload)/` — admin panel (`admin/[[...segments]]/`) and REST/GraphQL API (`api/[...slug]`, `api/graphql`).

**Content model**: `Pages` and `Posts` are both versioned/draft collections (autosave + scheduled publish) with a shared SEO tab (`@payloadcms/plugin-seo`). Pages compose a `layout` of blocks from `src/blocks/` (Archive, Banner, CallToAction, Card, Code, Content, ContentMedia, Event, Form, Media, RelatedPosts), dispatched via `src/blocks/RenderBlocks.tsx`, plus a hero from `src/heros/` dispatched via `RenderHero.tsx`. Posts use Lexical rich text with embedded Banner/Code/MediaBlock features, categories (nested-docs plugin), and related posts.

**Access control** is centralized in `src/access/` (`anyone`, `authenticated`, `authenticatedOrPublished`, `adminAccess`, `editorAccess`, `checkRole`) and composed per-collection — reuse these rather than writing new access functions. Per-collection overrides live next to their collection in `access/`/`hooks/`/`fieldAccess/` subfolders (e.g. `Users/hooks/protectRoles.ts`).

**Revalidation**: `Pages`/`Posts` hooks (`revalidatePage.ts`, `revalidatePost.ts`) trigger Next.js on-demand revalidation on change/delete; `src/hooks/revalidateRedirects.ts` handles redirect revalidation globally.

**Plugins** are wired in `src/plugins/index.ts`: redirects, nested-docs (categories), SEO, form-builder, search (`src/search/`), S3 storage.

`src/payload-types.ts` is generated by `generate:types` — never hand-edit it (it's excluded from ESLint).

## Payload CMS skill

For anything touching `payload.config.ts`, collections, fields, hooks, access control, or the Payload Local/REST/GraphQL APIs, start with `payload/SKILL.md`, then drill into `payload/reference/*.md` (FIELDS, COLLECTIONS, HOOKS, ACCESS-CONTROL, ACCESS-CONTROL-ADVANCED, QUERIES, ADAPTERS, ADVANCED, PLUGIN-DEVELOPMENT, ENDPOINTS, FIELD-TYPE-GUARDS). It covers this codebase's patterns plus general Payload gotchas — e.g. the Local API bypasses access control unless `overrideAccess: false` is passed, and nested hook operations need `req` threaded through them to stay in the same transaction.
